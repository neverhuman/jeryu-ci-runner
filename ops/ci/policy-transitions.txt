# Authorized audit-policy transitions.
#
# The baseline always uses protected main's own agent/audit-policy.toml. A
# head whose policy differs from protected main's is refused unless this file
# -- read from the protected-main clone, never from the head under test --
# pins that exact change as one line:
#
#   <protected sha256> <candidate sha256>
#
# both of `sha256sum agent/audit-policy.toml`, protected main's first. A
# transition requires prior review: one change adds the pin here and merges
# before a head can request those policy bytes.
#
# What a matched pin buys, exactly: those two files may differ. Beyond the exact
# digest pair the guard re-checks one thing, the numeric minimum_score, and only
# that it did not go down -- no other field (hard_findings_allowed, [scan]
# excluded_paths, [dead_language] allow_terms, the required auditor version) is
# compared between the pair. Those bytes rest on the review that landed the pin.
# Nothing else about the gate moves: both audit runs still use main's effective
# floor, the baseline is still protected main's own tree, and the auditor's
# strict ratchet still demands policy_changed == false. Jankurai 1.7.6 rejects
# changed policy fingerprints, so this authorization alone cannot make a future
# policy migration pass. Such a migration needs reviewed auditor support for
# judging candidate code under main's policy.
#
# Blank lines and #-comments are ignored. Any other line shape refuses the
# whole file: a pin nobody can parse must not become a pin nobody checks.
#
# Historical 1.7.5 -> 1.7.6 version-only transition, already completed by PR171
# (ad7191181360eb418c6a1af4e501eba663c7ff83). Both sides are kept as full
# preimages so the pin is not a claim but a checkable fact: the protected side
# is ops/ci/tests/fixtures/audit-policy-1.7.5-preimage.toml (protected d19269ff)
# and the candidate side is agent/audit-policy.toml itself (ad719118).
# ops/ci/tests/test-proof-guards.sh hashes both, holds them to a version-only
# difference, and proves the pin is inert: main already carries the candidate
# bytes, so main's policy is never this pin's protected side and the pin
# authorizes no change to today's main.
