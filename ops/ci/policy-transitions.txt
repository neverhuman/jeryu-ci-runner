# Authorized audit-policy transitions.
#
# The baseline always uses protected main's own agent/audit-policy.toml. A
# head whose policy differs from protected main's is refused unless this file
# -- read from the protected-main clone, never from the head under test --
# pins that exact change as one line:
#
#   <protected sha256> <candidate sha256>
#
# both of `sha256sum agent/audit-policy.toml`, protected main's first. A
# transition requires prior review: one change adds the pin here and merges
# before a head can request those policy bytes. A pin may not lower
# minimum_score. Both audit runs use main's effective floor. A pin never
# rewrites the baseline or bypasses the auditor's policy_changed ratchet.
# Jankurai 1.7.6 rejects changed policy fingerprints, so this authorization
# alone cannot make a future policy migration pass. Such a migration needs
# reviewed auditor support for judging candidate code under main's policy.
#
# Blank lines and #-comments are ignored. Any other line shape refuses the
# whole file: a pin nobody can parse must not become a pin nobody checks.
